# VK → Discord: правила работы

- Перед правками читать README.md и DEVELOPMENT.md. Импорт v9 выполнен
  28.11.2026; постоянная папка исходников — vk_discord_publisher.
  Исходный v7 сохранён в коммите 5357621, хеши импорта — в SOURCE_IMPORT.json.
- Пользователь согласует этапы отдельно. Не переходить к следующему этапу
  или поддержке нескольких направлений публикации без его указания.
- Сейчас одобрены смена единственного сервера/канала и ручной выбор ожидаемой
  главы. Обсуждённый вариант ручного выбора: до успешной публикации, затем
  автоматический расчёт; предусмотреть возврат к автоматическому выбору.
- Держать пользователя в курсе архитектурных решений и объяснять изменения плана.
- При планировании явно разделять работу помощника и работу пользователя.
  Для пользовательских действий указывать момент участия, шаги и ожидаемый
  результат. Если действий от пользователя сейчас не требуется, говорить это прямо.
- Discord-канал текущей установки тестовый. Отправка реальных сообщений и
  удаление публикаций требуют соответствующего указания пользователя.
- Страницы публикуются в порядке VK, под спойлерами, тихими сообщениями.
  Объявление обычное: «Глава загружается в: <#thread>» до отправки страниц,
  «Опубликовано в: <#thread>» после подтверждения всей отправки.
- Успешная повторная публикация 1200 после card update v2 подтверждена пользователем.
- Сроки наблюдения не менять в рамках настройки Git и новых кнопок.
  Адаптивное наблюдение 5/10 минут остаётся отдельной отложенной доработкой.
- Не коммитить секреты, конфигурацию, журналы, состояние и скачанные главы.
- Сохранять изоляцию разработки и установленной программы. Не завершать все
  процессы Python, не обходить запреты доступа к установленным файлам.
- Пользователь не хочет веб-ссылки для скачивания. Выдавать локальные файлы
  в папке проекта. Не создавать новые папки с полными версиями вместо веток Git.
