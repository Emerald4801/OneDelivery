# Разработка

## Ближайшие действия

1. Получить актуальные исходники установленной v9 в `vk_discord_current/`.
   На этом этапе нужны только `.py` и `.ps1`, без конфигурации и секретов.
2. Сохранить импорт отдельным коммитом. Сверить его с исходниками обновления
   карточки и перенести актуальную версию в постоянную папку исходников.
   Не заменять v9 старым снимком v7 и не поддерживать две рабочие копии кода.
3. Реализовать согласованные настройки в отдельной ветке, выполнить проверки,
   показать результат пользователю и подготовить установку из зафиксированного
   состояния репозитория.

## Рабочий процесс

- `main` хранит принятые состояния проекта. Первый коммит — исходная точка
  доступных материалов, пока без полного исходника установленной v9.
- Для каждой доработки создаётся отдельная ветка. Коммит содержит связное
  изменение и описание выполненной проверки.
- Перед коммитом проверяются список файлов и изменения. Не использовать
  массовое добавление без проверки исключений.
- Версии различаются коммитами и тегами, а не новыми папками `v10`, `v11` и т. п.
- Файлы для пользователя передаются через локальную папку проекта;
  не давать веб-ссылки на скачивание.
- Установка отделена от разработки: изменение Git-ветки не должно менять
  запущенную программу, её данные или запускать публикацию в Discord.

## Доступные проверки

Обновление карточки проверяется без настоящих токенов и отправки сообщений:

```powershell
python -m unittest discover -s vk_card_update_v2 -p test_card_update.py -v
python -m unittest discover -s vk_card_update_v2 -p test_shutdown.py -v
```

Нужны Python 3.10+, requests, Pillow. Второй набор интеграционных проверок
использует настоящие Windows-блокировки и временные профили; команды
Планировщика и запуск окна подменены. Контракт восстановления v9 задан явной
фикстурой, поскольку полный актуальный исходник ещё не импортирован.

## Git в среде помощника

Владелец рабочей папки и пользователь изолированной среды могут отличаться.
Если Git сообщает `dubious ownership`, помощник использует параметр
`-c safe.directory=<точный абсолютный путь проекта>` только для текущей команды.
Не применять `safe.directory=*` и не менять глобальные настройки доверия.

Если имя и email автора Git не настроены, для первоначального коммита
планируется технический автор `Codex <codex@local.invalid>` через параметры
команды. Личные и глобальные настройки пользователя не меняются.
