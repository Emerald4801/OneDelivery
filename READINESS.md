# OneDelivery: фиксация версии и проверка надёжности

Дата: 28 ноября 2026 года. Этап выполнен по указанию пользователя после
реальной проверки смены назначения и публикации. Обновление рабочей программы
и ручная проверка нового продолжения отправки отложены пользователем.

## Что проверено

| Область | Проверка и результат |
| --- | --- |
| Текущая установка | 40 из 40 рабочих файлов совпадают с принятым полным пакетом; все 9 закреплённых зависимостей совпадают с lock-файлами |
| Настройка автозапуска | Обе задачи включены, пути соответствуют установке; настроены триггеры входа для обработчика и окна, для обработчика есть ежедневный триггер |
| Восстановление задачи | RestartCount=999, интервал 1 минута, нет ограничения времени исполнения, StartWhenAvailable включён, работа на батарее разрешена |
| Права и повторный запуск | Обе задачи используют Interactive/Limited и IgnoreNew; определения проверены чтением, новые задачи не регистрировались |
| Запуск без сети | Настоящий entrypoint повторяет проверку Discord и после восстановления переходит к контроллеру; API и ожидание в этом тесте подменены |
| Пауза и ручная глава | Перезапуск сохраняет паузу и ручной номер; самовольно публикацию не начинает |
| Второй обработчик | Отдельный процесс отвергается настоящей Windows-блокировкой до чтения токена и изменения статуса первого экземпляра |
| Блокировка отправки | Другой процесс не может захватить publisher.lock, после освобождения захват возможен |
| Второе окно | Второй процесс передаёт сигнал существующему; после закрытия экземпляра новый может запуститься |
| Закрытие окна обновлением | Проверено настоящее событие Windows на отдельном тестовом процессе; управление публикацией не меняется |
| Одновременные команды | Три отдельных процесса сохраняют один общий запрос ручной проверки |
| Новое назначение в окне | При новом запуске entrypoint читает изменённый config и управление нового канала; создание самого Tk-окна в этом тесте подменено |
| Ручной запуск и Resume | Настоящий PowerShell-скрипт проверен для Running/Ready и Enabled/Disabled; изменяющие команды Планировщика подменены |
| Определение задачи | Настоящие New-ScheduledTask cmdlets создали определение только в памяти; регистрация, остановка и удаление задач запрещены тестовыми заглушками |
| Частичная отправка | Проверены 6/16 страниц, принятые Discord 12/16 при потерянном ответе, повтор без связи и перезапуск; лишних карточек и страниц нет |
| Потеря первого ответа | Потерянные ответы на создание карточки и ветки восстанавливаются; pending-квитанция другого бота отвергается |
| Сохранность данных | Изменённый состав, повреждённые или отсутствующие файлы блокируют продолжение; правило происхождения публикации и 72 часа сохраняются |
| Обновление | Полный и узкий архивы проверены на временных копиях текущего установленного кода: применение, повтор, откат; тестовый файл токена не изменился |

## Результаты запусков

| Набор | Результат |
| --- | --- |
| Корневые test_*.py | 147 проверок: 144 прошли, 3 отдельно выполнены с разрешённым доступом Windows |
| Отдельные Windows-проверки | 2 DPAPI на одноразовых строках и 1 CIM-preview прошли; это те же 3 проверки, не добавочные |
| onedelivery_update/test_*.py | 17 прошли |
| vk_card_update_v2/test_card_update.py | 10 прошли |
| vk_card_update_v2/test_shutdown.py | 7 прошли |

Всего подтверждена 181 уникальная проверка. Новых в этом этапе — 19:
15 жизненного цикла, 3 восстановления и 1 совместимости сборки.

Реальные Windows mutex, файловые блокировки, события и отдельные процессы
использовались с временными профилями. Настоящие сообщения VK/Discord,
настоящие токены и изменяющие операции системного Планировщика в тестах
не использовались. Режим и исходники установленной программы не менялись.

## Исправления по результатам

Pipeline.existing раньше отвергал карточку, которую Discord создал, но ответ
на POST потерялся до записи card_id. Добавлена проверка подходящей pending-
квитанции и передача управления уже существующему восстановлению издателя.
Новая карточка не создаётся; ограничения по автору, номеру, числу страниц
и уникальности совпадения сохраняются.

Сборщик узкого пакета использовал только хеши первого пакета настроек.
Он переведён на все известные проверенные версии, как полный сборщик.
Повреждённые или неизвестные исходники по-прежнему не принимаются.

## Контрольные точки и оставшиеся проверки

- installed-2026-11-28 — код полного пакета, установленного пользователем
  и сверенного по всем 40 файлам. Это точка возврата к принятой установке.
- tested-2026-11-28 — исходники после этапа проверок. Содержат подготовленное
  новое восстановление; оно пока не установлено в AppData.
- Реальная перезагрузка, выход/вход в Windows и сон компьютера в этом этапе
  не выполнялись. Проверено наличие и содержимое триггеров, а не сам вход.
- Повторный обрыв VPN на новой установленной сборке остаётся пользовательской
  проверкой после отложенного обновления. Автоматические тесты заменяют API.
- Поиск 12:00–24:00 МСК, обычные интервалы и ручное управление сохранены.
  Изменение ночной политики восстановления и адаптивные 5/10 минут не входили
  в этот этап.
- Отображение старой ошибки ручной проверки рядом с работающей автоматикой
  и заметность ошибок сохранения остаются предложением для следующего этапа.

Этот отчёт подтверждает перечисленные проверки, а не объявляет программу
проверенной во всех условиях эксплуатации.
