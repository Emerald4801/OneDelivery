# OneDelivery — VK → Discord

Личная Windows-утилита для публикации новых глав One Piece из альбомов
сообщества VK 334424 в один выбранный Discord-канал с веткой для каждой главы.

## Состояние на 28 ноября 2026

Рабочая установленная программа — v9 с интерфейсом, треем, настройками
назначения и ожидаемой главы, поддержкой каналов объявлений. Полное обновление
установлено пользователем; все 40 рабочих файлов сверены с пакетом.
28 ноября 2026 года пользователь подтвердил успешную смену сервера/канала
и публикацию глав; оформление и результат его устраивают. Перед этим смену
блокировала проверка недостаточных прав бота; после исправления прав она прошла.
Ранее также подтверждена повторная публикация главы 1200 после `vk_card_update_v2`.

**Исходники установленной v9 импортированы 28 ноября 2026 года.**
Импорт сохранён отдельным коммитом с SHA-256 каждого исходного файла.

## Реализованные настройки

Ветка `codex/onedelivery-settings`: простая смена единственного сервера/канала,
ручной выбор ожидаемой главы и возврат к автоматическому выбору. Исправлен
выбор каналов объявлений: поддерживаются обычные текстовые каналы и объявления,
а также соответствующие им публичные ветки Discord. Ручной номер
сохраняется до подтверждённой публикации; ошибки и отсутствие альбома его
не сбрасывают. Полная существующая глава повторно не отправляется.

Смена назначения проверяет доступ только чтением, штатно останавливает
обработчик между циклами и заменяет обе связанные задачи Windows. Старые
публикации и история остаются в папках своих каналов. Новое назначение на паузе
до команды пользователя. В пустом канале можно явно выбрать первую ожидаемую
главу; без неё сохраняется прежняя безопасная начальная точка без отправки архива.

**Поддержка каналов объявлений установлена; успешная смена назначения
и публикация подтверждены пользователем.** Ручной номер и возврат к автоматике
проверены автоматическими тестами; отдельное подтверждение этих кнопок
в рабочем интерфейсе не записано.

В исходниках подготовлено продолжение частично отправленной
главы без повторного десятиминутного наблюдения. При следующей успешной
проверке соединения программа сверяет состав VK, сохранённые файлы и историю
Discord, затем досылает недостающие группы в прежнюю ветку. Повреждение файлов
или изменение состава останавливает продолжение. Это исправление ещё не
установлено по просьбе пользователя; новый полный архив собирается из основной ветки. Первичное наблюдение
новой главы и интервалы сетевых повторов не менялись.

Также исправлено восстановление при потерянном ответе на создание карточки:
существующая карточка передаётся издателю для продолжения, вторая не создаётся.
Проверка надёжности и границы подтверждения описаны в [READINESS.md](READINESS.md).

Подготовлены понятные статусы интерфейса: причина ожидания, дата следующей
попытки и обратный отсчёт, подтверждённые страницы и продолжение отправки.
Результат предыдущей ручной проверки показывается отдельно от текущей ошибки.
Отказ сохранения назначения выделяется красным сообщением «Настройки не
сохранены» с причиной и возможностью повторить сохранение. Эти изменения,
как и новое восстановление, пока не установлены по просьбе пользователя.
Результаты проверки — [onedelivery_update/STATUS_TESTING.md](onedelivery_update/STATUS_TESTING.md).

Подготовлена единая обработка ошибок. При временном обрыве сети ручная
проверка остаётся активной и повторяется через пять минут даже при выключенной
автоматике. Начальная проверка подключения повторяется через минуту. Срок
сохраняется на диске как календарное время и переживает перезапуск. Кнопка
«Повторить сейчас» запускает ту же операцию; ожидающий ручной повтор можно
отменить с сохранением уже отправленных страниц. При ошибке прав, ключа,
целостности файлов или конфликте глав работа приостанавливается до устранения
причины и явной команды пользователя. Начатая глава завершается прежде поиска
следующей, в том числе после полуночи; часы поиска новых глав остаются прежними.
Подробности и результаты проверок —
[onedelivery_update/RECOVERY_TESTING.md](onedelivery_update/RECOVERY_TESTING.md).
Этот этап также подготовлен без обновления рабочей установки.

Добавлены сведения о сборке и окно «Диагностика…». Установщик записывает
идентификатор коммита, дату сборки и хеши установленного кода; окно показывает
сборку и дату по Москве. Несовпадение файлов обозначается как изменение кода.
Диагностика проверяет локальный доступ, состояние обработчика и обеих задач
Windows. Связь с VK/Discord проверяется отдельной кнопкой без публикации.
Отчёт сохраняется в `diagnostics/` установленной программы и содержит только
выбранные сведения о состоянии и событиях. Конфигурация, секреты и исходные
журналы в него не копируются. Сведения о сборке откатываются вместе с кодом.
Отчёт этапа — [onedelivery_update/DIAGNOSTICS_TESTING.md](onedelivery_update/DIAGNOSTICS_TESTING.md).
Установка новых изменений остаётся отложенной пользователем.

Для полного обновления существующей программы подготовлены
`INSTALL_ONEDELIVERY.cmd` и `OneDelivery_full.zip`. Пакет заменяет все 44 рабочих
файла, сохраняя существующую папку AppData, оба токена, config, state, значок
и виртуальную среду. Повторная настройка не запускается. Старые пакеты для
этой установки не нужны. Подробности — `onedelivery_update/README_FULL.txt`.
Сборка полного архива: `python onedelivery_update/build_full_package.py`.

Узкий пакет `UPDATE_ONEDELIVERY.cmd` / `OneDelivery_settings_update.zip`
сохранён для прежнего способа обновления. Для новой полной сборки используйте
`INSTALL_ONEDELIVERY.cmd`. Исторический `vk_discord_publisher/install.ps1`
не используется новым полным пакетом; не запускайте его для этого обновления.

После успешной проверки полного обновления старые `transfer_*`, `card_transfer*`,
`git_transfer_*` и `handoff_transfer_*` можно убрать. Фактический список из 13 папок
сохранён локально в `CLEANUP_ONEDELIVERY.txt`. Папку проекта с `.git`, исходниками
и тестами, а также `%LOCALAPPDATA%\VKDiscordPublisher` нужно сохранить.

Наблюдение остаётся 10 минут (снимки 0, 5, 10), поиск — раз в 30 минут,
12:00–24:00 МСК. Адаптивное наблюдение и дальнейшие этапы продакшна отложены.

## Репозиторий и установка

Git хранит исходники, тесты и документы. Токены, конфигурация, скачанные главы,
история публикаций и журналы остаются вне репозитория. Архивы и вспомогательные
файлы переноса также не отслеживаются. `.gitignore` использует список разрешённых
папок; для добавления новой папки исходников его нужно явно обновить.

Репозиторий опубликован на [GitHub](https://github.com/Emerald4801/OneDelivery).
Ветка `main` объединяет настройки, полный пакет, продолжение прерванной отправки
и проверки надёжности. Ветки доработок сохраняют отдельную историю изменений.
Установленная версия с настройками отмечена `installed-2026-11-28`, исходники
после проверок — `tested-2026-11-28`. Новое продолжение отправки в AppData
пока не установлено; обновление и ручная проверка отложены пользователем.
Этап понятных статусов отмечен отдельно: `tested-status-2026-11-28`.
Единая обработка ошибок — `tested-recovery-2026-11-28`.
Версия и диагностика — `tested-diagnostics-2026-11-28`.
Четыре исходных коммита сохранены с прежними идентификаторами; начальный
коммит GitHub с README связан с ними отдельным коммитом объединения.

Локальный Git работает через разрешённый дополнительный доступ к `.git`.
Первый коммит `5357621` содержит исходный v7 и передачу, `730dd5f` — импорт v9.
Удалённый адрес `origin` настроен на этот репозиторий GitHub.
Глобальные настройки доверия Git не менялись.

Порядок дальнейшей работы описан в [DEVELOPMENT.md](DEVELOPMENT.md).
