# OneDelivery: Windows CI и общая обработка Discord — 28 ноября 2026

Этап согласован после пользовательского подтверждения ручной проверки
предыдущей сборки. Пользователь также поручил явно разделять работу помощника
и собственные действия. Это правило сохранено в AGENTS.md.

Работа помощника: настройка CI, устранение проблем тестовой среды, небольшое
упрощение кода, проверки, сохранение Git и подготовка локальных пакетов.
Работа пользователя: на этом этапе действий не требуется. Новая установка
и реальные сообщения не выполняются помощником в рамках CI.

## Автоматические проверки

Workflow Windows checks запускается при push в main/codex и PR в main.
Две среды: windows-2022, Python 3.10 и 3.12. Зависимости устанавливаются
из существующих lock-файлов без их изменения. Actions закреплены полными SHA;
workflow получает contents:read. Секреты OneDelivery не используются.
История Git и теги загружаются полностью для фикстур v7 и прежних пакетов.

Выбор fetch-depth и отсутствие сохранённых credentials основаны на
[документации checkout](https://github.com/actions/checkout/tree/v7.0.1);
настройка Python и кэша — на
[документации setup-python](https://github.com/actions/setup-python/tree/v7.1.0).

`python ci/check.py --native-windows` выполняет тот же набор локально.
Каждый набор unittest идёт отдельным процессом. Включены настоящие скрытые
Tk-окна, тестовые DPAPI и определение задачи Windows только в памяти.
Любая ошибка, пропуск теста или нулевое число найденных тестов завершает CI
с ошибкой. Это отдельно проверено четырьмя временными примерами: успешный тест,
падающий тест, пропущенный тест и пустой набор дают ожидаемый код возврата.

Первые запуски на GitHub выявили короткий путь профиля RUNNER~1 вместо
runneradmin в тестах. Исправлены тестовые профили через Path.resolve(),
включая сравнения путей задач и внедрение отказа обновления. Проверки сохранены,
условия успеха не ослаблялись. До изменения приложения прежние 244 теста
и 10 сочетаний пакетов прошли на обеих версиях Python:
[запуск исходного набора](https://github.com/Emerald4801/OneDelivery/actions/runs/46170893911).

## Изменение кода

Общая обработка запросов, сетевых ошибок, rate limit и неопределённого POST
находится в publisher_runtime.Discord. publish_album_v3.Discord использует
её, переопределяя тайм-аут и упаковку галереи. Файлы удерживаются через ExitStack
до завершения запроса и закрываются при любой ошибке. Повтор открывает их заново.

Сохраняются пределы 120/180 секунд, 5 транспортных попыток, параметры,
JSON/nonce, имена вложений, порядок, спойлеры и тихие сообщения. Потерянный
ответ и HTTP 5xx на POST дают UnknownResult после одной попытки; проверка
истории и квитанции остаётся обязательной перед продолжением. Паузы,
расписание, выбранная глава и форматы сохранённого состояния не менялись.

Устранены два прежних различия: оба клиента отклоняют полный URL вместо
относительного API-маршрута, оба используют Retry-After для HTTP 429 с JSON
не в форме объекта. Эти случаи сначала воспроизведены новыми тестами на
прежнем коде, затем прошли после выделения общей логики.
