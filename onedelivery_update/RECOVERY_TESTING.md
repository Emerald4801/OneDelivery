# OneDelivery: единая обработка ошибок — 28 ноября 2026

Следующий этап версии и диагностики описан в
[DIAGNOSTICS_TESTING.md](DIAGNOSTICS_TESTING.md). Этот отчёт сохраняет результаты
контрольной метки tested-recovery-2026-11-28.

Этап согласован пользователем после подготовки понятных статусов. Изменения
сохраняются в Git и локальных пакетах. Установленная программа, её токены,
задачи Windows и реальные сообщения VK/Discord в этом этапе не менялись.

## Правила восстановления

| Причина | Поведение |
| --- | --- |
| Нет соединения, тайм-аут, оборванный ответ, HTTP 408/425/429/5xx | Повтор подключения через 60 секунд, цикла через 300 секунд |
| Ответ на отправку Discord не получен | Сначала сверка квитанции и истории; подтверждённые группы повторно не отправляются |
| Временный сбой ручной проверки | Та же операция и глава продолжаются автоматически, даже при ручной паузе автоматики |
| Перезапуск или выключенный компьютер | Абсолютный срок хранится на диске; просроченная попытка доступна после запуска |
| Ошибка ключа, прав, сертификата, повреждение файлов, конфликт глав, неизвестная ошибка | Работа приостанавливается, причина сохраняется; требуется исправление и явная команда пользователя |
| Несколько незавершённых глав или пропавший исходный альбом | Продолжение блокируется до проверки причины |

Сроки 60/300 секунд сохраняют прежние интервалы. Внутренние ограниченные повторы
транспортного чтения также остаются. VK API сохраняет различие сетевых ошибок,
ограничения частоты и отказов доступа при передаче ошибки через VKSource.
Неизвестный ответ не принимается за отсутствие новой главы.

Во время ожидания ручного повтора доступны «Повторить сейчас» и «Отменить
ручную проверку». Повтор использует прежний ID, номер и квитанцию. Отмена
сохраняет отправленные страницы и паузу автоматики; последующая ручная проверка
может продолжить эту главу. Активная отправка принудительно не прерывается:
отмена требует свободного publisher.lock и повторной проверки операции.
Поздний ответ отменённой операции не возвращает её в очередь.

Начатая публикация текущего бота в текущем канале имеет приоритет перед
следующей главой, включая случай пустой истории полных глав. Она может
завершаться после полуночи. Поиск новых глав остаётся 12:00–24:00 МСК раз
в 30 минут, первичное наблюдение — 0/5/10 минут. Пауза после автоматической
публикации остаётся 72 календарных часа. Адаптивное наблюдение сюда не входит.

Всего подтверждено 225 уникальных проверок. Отдельные запуски Windows и

После финальной правки классификации обрыва ответа и TLS повторно проверены
затронутые транспортные сценарии, издатель и восстановление.

Проверены продолжение 6/16 страниц и потерянный ответ после принятия группы,
сохранение ручного ID и номера на паузе, календарный срок после перезапуска,
немедленный повтор, отмена и гонка с захватом блокировки. Проверены постоянный
отказ прав и повреждённый кэш без бесконечных повторов, блокировка до чтения
ключей при повторном запуске, ручная команда во время недоступности подключения
и возобновление обработчика после блокирующей ошибки. Отдельно проверены
пустая история Discord, несколько pending-квитанций, приоритет начатой главы,
продолжение после полуночи и отказ при исчезнувшем исходном альбоме.

Настоящее окно проверено на кнопках повтора и отмены: операция сохраняет ID,
автоматика остаётся на паузе, после отмены история отображается нейтрально.
Определение задачи Windows создавалось только в памяти, без регистрации.
Проверка синтаксиса compileall и git diff --check выполнена.

## Пакеты и ограничения

Полный архив содержит 41 рабочий файл, узкий — 14. В оба включены новый
failure_policy.py и изменённые модули источника/загрузки. В реестре совместимости
сохранены хеши предыдущего состояния 8255bca. Контрольная метка этапа —
tested-recovery-2026-11-28; прежние метки не перемещаются.

Оба пакета применены к временным копиям четырёх состояний Git:
installed-2026-11-28, tested-2026-11-28, tested-status-2026-11-28 и e3f3d68.
Во всех восьми сочетаниях проверены замена, повторная установка без изменений,
откат и сохранность тестовых config/токенов. Откат удаляет новый модуль,
которого не было в прежнем состоянии. Состав ZIP, CRC и хеши полезной нагрузки
сверены с исходниками. Настоящая AppData в этих проверках не использовалась.

Автоматические проверки используют временные папки, подменённые API и
управляемое время. Реальный VPN, сон/перезагрузка компьютера, публикация
и новый интерфейс на установленной программе остаются последующей
пользовательской проверкой после отложенного обновления. Эти результаты
не заменяют её и не объявляют завершение подготовки к продакшну.
