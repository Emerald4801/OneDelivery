# Проверки обновления v2

27 ноября 2026. Windows, Python 3.10.11 и Windows PowerShell 5.1.

## Проверено

- 10 проверок публикации из test_card_update.py: загрузка/готовность одной карточки,
  компактное упоминание ветки, обычная карточка и тихие страницы, спойлеры, порядок
  16 страниц, возобновление после потерянного ответа, восстановление финального
  статуса без новых POST, сохранение завершённых старых карточек, идемпотентность,
  отказ на несовместимом коде, откат двух файлов при ошибке второй замены.
- 7 проверок test_shutdown.py. Среди них реальные Windows mutex и файловая
  блокировка установленного приложения в одноразовых профилях: ожидание задержанного
  завершения после того, как Планировщик уже сообщает Ready; отмена по таймауту
  без замены исходников и без трассировок; блокировка apply отдельной файловой
  блокировкой; удержание блокировок во время обеих замен. Также проверены ожидание
  и отдельная обработка ошибок доступа.
- В одной из семи проверок дополнительно проходят все четыре сочетания прежнего
  состояния задачи: Running/Ready и Enabled/Disabled, включая повторную установку.
- Тесты проверяют сохранность конфигурации и тестовой истории.

## Границы проверки

Команды Планировщика и запуск окна в интеграционных тестах подменены: тесты
не меняют настоящие задачи Windows, не запускают реальный интерфейс и не отправляют
сообщения в Discord. Выполнение PowerShell, Python, блокировок и замены файлов
настоящее. Тестовые процессы завершаются только по их собственным объектам Popen.
Установщик не содержит принудительного завершения процессов.

В рабочей папке доступен исходный снимок v7, поэтому контракт восстановления
незавершённых публикаций v9 задан явной фикстурой. Полный исходник установленной
v9 из этой среды прочитать нельзя. Установщик проверяет структуру фактической v9
перед изменениями и не заменяет её целиком старым снимком.

Запуск проверок из корня проекта, где есть vk_discord_publisher с исходниками v7:

    python -m unittest discover -s vk_card_update_v2 -p test_card_update.py -v
    python -m unittest discover -s vk_card_update_v2 -p test_shutdown.py -v

В тестах не нужны настоящие токены или доступ к сети. Нужны зависимости исходного
проекта requests и Pillow. Временные профили и виртуальная среда удаляются после
проверок. Реальную установку и новую публикацию пользователь проверяет отдельно.
