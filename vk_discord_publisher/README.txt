ВК -> Discord: первая публикация главы, Windows
=============================================

1. Полностью распакуйте архив в отдельную папку.
2. Запустите SETUP.cmd. Нужен Python 3.10+; зависимости установятся автоматически.
3. Введите токен бота (ввод скрыт), ID сервера и ID обычного текстового канала.
   Все данные вводятся локально. Токен в чат отправлять не нужно.
   SETUP проверяет подключение и основные права, ничего не публикует.
4. Запустите PUBLISH_ALBUM.cmd. Укажите ссылку на альбом, название главы и число
   фотографий со счётчика ВК (последнее можно пропустить).
   Для тестового альбома: https://vk.ru/album-334424_310875314
   Название: One Piece — глава 1199. Фотографий: 12.
   Нажатие Enter на последнем поле запускает скачивание и затем публикацию.
5. В канале появится карточка главы с веткой. Внутри — по одной фотографии на
   сообщение в порядке альбома. В конце карточка получает статус «Опубликовано».

Если глава уже скачана старой программой, вместо пункта 4 запустите
PUBLISH_LOCAL.cmd: вставьте путь к папке с JPG и manifest.json и название главы.
После ввода названия начнётся проверка файлов и публикация; ВК не запрашивается.

ГДЕ ВЗЯТЬ ID КАНАЛА
В Discord включите Настройки пользователя -> Расширенные -> Режим разработчика.
Правой кнопкой по нужному текстовому каналу -> Копировать ID канала.
Нужен именно ID канала. ID сервера его не заменяет. Категория, готовая ветка,
форумный канал и личные сообщения в этой версии не поддерживаются.

ПРАВА БОТА В ВЫБРАННОМ КАНАЛЕ
View Channel, Send Messages, Attach Files, Read Message History,
Create Public Threads, Send Messages in Threads.
Проверяются роли и переопределения именно канала; Administrator не требуется.
Особые ограничения сервера могут обнаружиться при реальной публикации.
CHECK_CONNECTION.cmd повторяет только проверку, без отправки сообщений.

ТОКЕН
При доступном Windows DPAPI сохраняется в token.dpapi под вашей учётной записью.
Если шифрование недоступно, токен не сохраняется и запрашивается при следующем
запуске. Открытый текст токена вместо шифрования автоматически не записывается.
В config.json находятся только ID и настройки, не токен. Перенос на другой ПК
или другую учётную запись может потребовать повторного SETUP.cmd.
Программы вашей учётной записи потенциально могут расшифровать этот файл;
это защита от простого чтения файла, не от доступа к вашему сеансу Windows.
Скрипт не печатает токен, не добавляет его в сообщения или манифесты.
Для замены токена повторите SETUP.cmd. При необходимости поддерживается
переменная окружения DISCORD_BOT_TOKEN; она имеет приоритет при check/publish.
Не передавайте другим рабочую папку с token.dpapi или cookies.txt.

УЖЕ СКАЧАННЫЙ АЛЬБОМ
Можно обойтись без повторного обращения к ВК. После SETUP.cmd откройте PowerShell
в папке новой программы и выполните, подставив реальный путь к старому альбому:
  .\.venv\Scripts\python.exe publish_album.py publish --folder "C:\путь\к\album-334424_310875314" --title "One Piece — глава 1199"
Нужна папка с JPG и manifest.json. CBZ сам по себе не используется.
Либо из PowerShell:
  .\PUBLISH_ALBUM.cmd --folder "C:\путь\к\album-334424_310875314" --title "One Piece — глава 1199"
Исходная папка при этом не изменяется. Состояние отправки сохраняется в новой папке
программы, внутри state. Для новых альбомов используется downloads этой программы.

ЕСЛИ ДЛЯ ВК НУЖЕН ВХОД
Как в предыдущем загрузчике: положите свой Netscape cookies.txt для ВК рядом со
скриптом. Он будет использован только при скачивании из ВК.
Альтернатива: .\PUBLISH_ALBUM.cmd --browser firefox (также chrome или edge).
Чтение cookies Chrome/Edge может быть заблокировано защитой Windows/браузера.
Не отправляйте cookies в чат и не устанавливайте случайные расширения для экспорта.
Если указан --browser, локальный cookies.txt игнорируется.

ПОВТОРНЫЙ ЗАПУСК И ОШИБКИ
- Программа сверяет локальные контрольные суммы, историю карточек и ветки.
- Уже опубликованные страницы пропускает. После потерянного ответа сначала
  сверяет историю, а не отправляет файл повторно вслепую. Есть стабильные nonce.
- Два экземпляра из одной папки блокируются; не запускайте копии программы
  одновременно из разных папок на один альбом и канал.
- При HTTP 429 учитывается задержка Discord. Временные ошибки чтения повторяются.
- При неоднозначном результате POST программа останавливается с сохранённым
  прогрессом: повторный запуск сверит историю перед продолжением.
- Если страница удалена в середине, автоматическая вставка не выполняется: это
  нарушило бы порядок сообщений. Скрипт остановится для ручной проверки.
- При изменении состава/файлов альбома или смене бота прежняя публикация
  автоматически не меняется. Не удаляйте state для принудительного повтора.
- Служебные метки [vk-album:...] и [vk-page:...] нужны для восстановления. Не
  редактируйте их и не удаляйте сообщения во время работы скрипта.
- Проверка истории ограничена 10000 сообщениями на канал/ветку; при превышении
  программа остановится. Рекомендуется отдельный личный канал для глав.
- Публикация использует тихие сообщения без упоминаний. Картинки не сжимаются.
- В config.json есть max_file_mib=8: консервативная локальная граница одного файла,
  а не утверждение о тарифном лимите Discord. Её можно изменить после проверки
  доступного лимита. Discord может отдельно отклонить вложение; размер запроса
  также ограничен. Автоматически ухудшать качество программа не будет.
- Архивированная ветка при необходимости продолжения открывается повторно;
  если она заблокирована и прав недостаточно, потребуется ручное действие.

ГРАНИЦЫ ЭТОЙ ВЕРСИИ
Это ручной импорт по ссылке или локальной папке — первый этап плана.
Поиск новых альбомов, расписание, каталог и slash-команды ещё не добавлены.
Бот использует HTTP API и может отображаться Offline: это не мешает отправке.
Не нужно включать Message Content Intent для чтения собственных сообщений бота.
На реальном Discord-боте программа в этой сессии не проверялась. Локальные тесты
проверяют публикацию, восстановление, порядок и ошибки на подставных ответах API.

ФАЙЛЫ И ОБНОВЛЕНИЯ
publish_album.py — публикация и настройка; download_album.py — проверенный ранее
загрузчик. Для обновления библиотек в PowerShell:
