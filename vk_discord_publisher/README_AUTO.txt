Автоматический режим VK → Discord

Проверка официального API (новый вариант источника)
PROBE_VK_API.cmd — ввести ключ локально скрытым вводом и проверить:
список альбомов сообщества, фотографии главы 1199, порядок относительно ранее
проверенного manifest.json, скачивание первой страницы. Сообщений в Discord нет.
При ошибке ключ не сохраняется. При успехе ключ защищается DPAPI и сохраняется
в %LOCALAPPDATA%\VKDiscordPublisher\vk_api_token.dpapi.
Отчёт без ключа: diagnostics\vk_api_probe.json в той же рабочей папке.
Наличие клиента API не означает, что конкретный ключ имеет нужный доступ.
Если API отклоняет метод, программа показывает код и не подменяет результат
пустым списком или незаметным переходом к HTML.
В режиме API и альбомы, и фотографии читаются через официальный API;
gallery-dl, HTML-список и браузерная сессия для этого не используются.
Проверка сама не меняет выбранный источник и не включает расписание. Наличие
сохранённого ключа тоже не переключает программу на API. Установщик выбирает
API по успешному отчёту с подтверждённым порядком, затем проверяет VK и Discord.
Если PROBE_VK_API.cmd уже завершился успешно, повторять его при обновлении не нужно.

INSTALL_AUTO.cmd — создать рабочую папку %LOCALAPPDATA%\VKDiscordPublisher,
перенести существующие локальные настройки, подготовить зависимости, выполнить проверку без отправки,
зарегистрировать задачу Windows и запустить её. При неуспешной проверке задача
не создаётся и публикация не включается. Нужны уже сохранённые config.json и
token.dpapi от существующего бота. Токен в чат отправлять не нужно.

CHECK_AUTO.cmd — проверить доступ к списку альбомов VK, фотографиям альбома,
Discord и последней полной главе. Ничего не публикует и не скачивает страницы.
STOP_AUTO.cmd — выключить задачу и остановить её процесс с сохранением прогресса.
START_AUTO.cmd — обычный запуск с видимой консолью, без установки автозапуска.

Расписание
- При входе в Windows запускается фоновый процесс под текущим пользователем.
  Администраторские права и пароль Windows не требуются. До входа пользователя
  программа не работает. При выключенном/спящем компьютере проверок нет.
- Поиск новых альбомов: 12:00–24:00 по Москве, раз в 30 минут.
- После обнаружения непустого альбома: проверки раз в 5 минут; минимум три
  успешных наблюдения за 10 минут. Сравниваются состав и порядок фотографий.
- Найденный до полуночи альбом продолжаем проверять после полуночи.
- После перезапуска, сетевой ошибки или большого перерыва наблюдение готовности
  начинается заново. Пауза 10 минут — эвристика, а не гарантия завершения автором.
- После аварийного завершения Планировщик пытается перезапустить программу
  через минуту. Второй экземпляр для того же канала блокируется в текущей сессии
  Windows, даже при запуске из другой папки.

Номера и источник
- Ожидаемая глава определяется по последней полной публикации бота в Discord.
  Локальная история завершённых отправок не заменяет эту проверку.
- Если канал пуст при первом запуске, начальная точка — последняя непустая
  доступная глава в VK. Старый архив автоматически не отправляется.
- Ищем строго следующий номер, пропущенные номера не перескакиваем.
- Пустые альбомы с тем же названием не блокируют заполненный альбом.
  Если заполненных кандидатов несколько, автоматический выбор останавливается.
- В режиме API каждая получасовая проверка читает весь список альбомов с
  пагинацией. Во время пятиминутного наблюдения читаются известные кандидаты.
  Перед отправкой снова выполняется полный обход.
  В веб-режиме обычный поиск читает свежую часть списка и сохраняет кандидатов.
  Динамическая пагинация VK может оказаться недоступной парсеру: это ограничение
  веб-способа, которое нужно подтвердить на реальной сессии. При необходимости
  используется официальный photos.getAlbums с VK_API_TOKEN в окружении.
- Страница входа, проверка браузера и нечитаемый ответ — ошибка доступа, а не
  «новой главы нет». Сетевые ошибки Discord не считаются удалением сообщений.

Публикация
- Сначала полностью скачать изображения, затем перепроверить состав альбома.
- Карточка: ГЛАВА N, Страниц: число, ссылка на ветку.
- В ветке: пачки до шести изображений под спойлерами, «Страницы 1-6».
- Перед отправкой сверяется отсутствие уже полной копии.
- После прерывания сохранённое состояние помогает сверить отправленные пачки
  и продолжить. Неоднозначное/изменённое состояние останавливает отправку.
- Старые опубликованные сообщения автоматически не редактируются. CBZ в
  автоматическом режиме не создаётся. Оригиналы не уменьшаются.

Безопасность и обслуживание
- Пароли VK и основной профиль браузера программа не читает.
- Если без авторизации VK не работает, можно экспортировать cookies только VK
  и импортировать IMPORT_VK_SESSION.cmd. Они сохраняются в vk_cookies.dpapi
  с защитой Windows. Исходный текстовый экспорт после импорта можно удалить.
  Старый cookies.txt также поддерживается, но он не зашифрован.
- DPAPI защищает данные для текущего пользователя; это не защита от программы,
  уже работающей с его правами. Не пересылайте папку с сохранённой сессией.
- Секреты, временные ссылки CDN и тела ответов не записываются в журнал.
- Журнал: logs\ongoing.log, с ротацией до четырёх файлов по 1 МБ.
  Текущее состояние: state\сервер\канал\watch_-334424.json.
- Обычный запуск не обновляет библиотеки. requirements.lock фиксирует версии;
  их обновление — отдельная операция с повторной проверкой программы.
- Рабочая папка автоматически размещается вне OneDrive и других синхронизируемых каталогов.

Границы проверки
Локальные тесты проверяют расписание, наблюдения, пустые дубликаты, порядок,
сбои и продолжение отправки на подставных ответах. Они не доказывают доступность
VK/Discord из вашей сессии и не заменяют живую диагностическую проверку.
